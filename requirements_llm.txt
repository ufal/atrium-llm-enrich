# requirements_llm.txt — multi-GPU inference stack (transformers + vLLM backends)
#
# NO STANDALONE `torch==` PIN, deliberately (issue atrium-project#10).
# vLLM pins torch EXACTLY -- `vllm 0.9.2` requires `torch==2.7.0`, `0.14.1` requires
# `2.9.1`, `0.22.0` requires `2.11.0`, `0.27.1` requires `2.13.0` -- so a second torch
# pin in this file cannot coexist with any vllm but the one matching it. Pinning
# `torch==2.7.0` here therefore did not pin torch, it pinned *vllm*: 0.9.2 was the only
# resolvable version, and it is the one that failed the v0.6.0 release gate on two
# fixable CRITICALs (CVE-2026-22778 remote code execution via invalid image, fixed in
# 0.14.1; CVE-2026-48746 authentication bypass, fixed in 0.22.0). Raising the vllm floor
# without removing this line would simply have made the install unsatisfiable.
#
# atrium-nlp-enrich reached the same conclusion from the other end: its Dockerfile does
# `sed -i '/^torch==/d' requirements_llm.txt` before installing. Dropping the line is the
# same fix stated once, in the file, rather than repaired at build time. The floor below
# now matches nlp-enrich's exactly, so both repos resolve the same GPU stack.
#
# `transformers>=4.57.6` stays as the FLOOR THIS REPO REQUIRES, but it is no longer the
# effective one: vllm 0.27.1 requires `transformers>=5.5.3` and wins. Dependabot ignores
# `transformers >= 5.0.0` here and in nlp-enrich, which stops it PROPOSING a 5.x bump --
# it does not stop pip resolving one when vllm demands it, and nlp-enrich has shipped
# under exactly that shape since v0.19.0.

pydantic==2.13.5
