# 🗺️ Plan — [\#13](https://github.com/ufal/atrium-llm-enrich/issues/13): The intermediate steps — data format to use

> _Further actions required, refreshed 2026-07-31 against the `test`-branch HEADs of all six repos. Findings and evidence: `13.digest.md`._
> _Scope: the JSON plane (`atrium_document`) only. The MD and TEITOK planes are unchanged and their open items are carried in §F._

**Where this stands.** The design is settled and the template is byte-identical everywhere (`para-drift` green, verified independently). What remains is not design work — it is **making five independent implementations actually obey a contract the template does not enforce**. Three of the six repos lose data at a hand-off, and no test anywhere runs two tools in sequence.

**Ordering principle.** P0 fixes things that are broken *right now* in the canonical pipeline order. P1 closes the hole that let them happen and builds the test that would have caught them. P2 is convergence and cleanup. P3 is new capability. Do not start P3 before P1 lands — a converter built on a chain that breaks at stage 4 cannot be validated.

## P0 — Chain-breaking defects (do first, in this order)

### P0.1 · `nlp-enrich`: write the record to the directory the caller asked for
**File:** `api_util/document_hook.py`
`run_document_hook()` declares `out_json: str` and never uses it. `DocumentRecord.open()` is called with no `out_dir`, so `__exit__` → `finalize()` writes `<doc_id>.document.json` into the **process CWD**. nlp-enrich's `entities` never reach the shared directory; llm-enrich reads a baseline with no entities in it.

Pass the path explicitly rather than relying on `out_dir` + the implicit filename, so the caller's `out_json` is authoritative:

```python
with DocumentRecord.open(doc_id, "nlp-enrich", baseline=baseline_json,
                         run_id=run_id, paradata_ref=paradata_ref) as doc:
    ...
    doc.finalize(out_json)          # ← was missing entirely
```

**Verify:** run `summarize_nt_udp.py --document-json-dir <dir>` from a *different* CWD and assert the record lands in `<dir>`, not next to the shell.

### P0.2 · `nlp-enrich`: stop destroying co-owned fields in `entities[]`
**File:** `api_util/document_hook.py:100`
`set_block("entities", …)` wholesale-replaces a block that `BLOCK_FIELD_OWNERS` splits three ways. Switch to the field-level merge and drop the field this tool does not own:

```python
doc.merge_block("entities", entities)   # own_fields defaults to the table's nlp-enrich list
```

and remove the `"pid": {...}` initialiser at line 80 — `pid` belongs to llm-enrich. (Merging rather than replacing also means a re-run of nlp-enrich alone no longer wipes downstream contributions.)

### P0.3 · `nlp-enrich`: give `char_span` a real value, or change the entity key
**File:** `api_util/document_hook.py:78`
`char_span` is hardcoded `None` and is a component of `BLOCK_KEY_FIELDS["entities"]`. With it constant, the natural key collapses to `(page, line)` and **every entity after the first on a given line is silently dropped** by any downstream `merge_block`. Reproduced: 3 entities on one line → 1 row survives.

Two options — **prefer (a)**:

- **(a) Compute the real span.** The tokens already carry offsets through `parse_and_align_conllu`; emit `char_span: [start, end]` relative to the line. This makes the key genuinely unique and makes `entities[].char_span` usable for highlighting, which is what it was specified for.
- **(b) If (a) is not feasible now,** add an ordinal and change the key to `["page", "line", "ord"]` in `BLOCK_KEY_FIELDS` (hub change, so it must land in the same sweep as P1.1). Weaker — the ordinal is not stable across re-runs.

Do **not** ship (b) silently: whichever is chosen, the hub's `BLOCK_KEY_FIELDS` and the schema's `entities[]` must agree with it.

### P0.4 · `alto-postprocess`: make the API path merge like the CLI path
**File:** `service/text_api.py:220`
`set_blocks={"pages": page_metrics, "lines": lines_metrics}` clobbers page-classification's `category`/`category_confidence` and nlp's `teitok_surface`. Every CLI stage in the same repo already uses `merge_blocks`. Change to:

```python
merge_blocks={"pages": page_metrics, "lines": lines_metrics},
```

**Verify:** POST after a page-classification contribution; assert `category` survives.

### P0.5 · `translator`: fix the `translations` block shape
**Files:** `utils.py:159`, `utils.py:496`
The implementation writes `{<tgt_lang>: "<entire joined translated text>"}`. The schema and hub fixture define `{source_lang, target_lang, backend}`. Write the metadata the schema specifies; the translated text already persists via `derived_from.translated_xml`:

```python
doc.set_block("translations", {
    "source_lang": src_lang,
    "target_lang": tgt_lang,
    "backend": <lindat|ctranslate2|llm>,
})
```

This also removes the two-writers-overwrite-each-other problem between the ALTO and metadata paths. If a per-language record is genuinely wanted, that is a **schema change** (`translations` → array, or `translations[lang]` objects) and belongs in P1.1, not in a silent divergence.

### P0.6 · `translator`: resolve the dead entity-translation pass
**Files:** `utils.py:161-175`, `utils.py:498-512`
In the declared order `pc→alto→translate→nlp→llm`, `entities[]` does not exist yet when the translator runs, so `existing_entities` is always empty and the entire pass is unreachable. Decide explicitly — this is the one item here that needs a **product decision, not a fix**:

- **(a) Move entity translation to nlp-enrich or llm-enrich** (whichever runs after entities exist) and delete it from the translator. Reassign `entities[].translation_en` in `BLOCK_OWNERS`/`BLOCK_FIELD_OWNERS` accordingly.
- **(b) Add a second translator invocation after nlp-enrich** purely for entity surfaces. Costs a stage; keeps ownership as documented.
- **(c) Delete the pass** and accept that `entities[].translation_en` is never populated — then remove it from the schema and the ownership table too, so the contract stops promising it.

Whichever is chosen, the private `doc._data.get("entities")` access goes away with it (or is replaced by the public reader from P1.2), and the dynamic `translation_{tgt_lang}` field name must be reconciled with the table's `translation_en` — either generalise the table to a prefix rule or restrict the code to the declared field.

## P1 — Close the hole and build the missing safety net

### P1.1 · Hub: make the template enforce rule 2
**File:** `docs/templates/shared/atrium_document.py`
`_assert_owner()` checks `BLOCK_OWNERS` only, so the nominal owner of a **field-split** block may still `set_block()` it and erase every co-contributor. This single permission is the root cause of P0.2 and P0.4. Reject it:

```python
def _assert_owner(self, name: str) -> None:
    if name in RESERVED_KEYS:
        raise ValueError(f"{name!r} is maintained by the module, not a tool block.")
    if name in BLOCK_FIELD_OWNERS:
        self._complain(f"block {name!r} is field-split — use merge_block(), not set_block()")
    owner = BLOCK_OWNERS.get(name)
    if owner and owner != self.program:
        self._complain(f"block {name!r} is owned by {owner!r}, not {self.program!r}")
```

Ship it as a **warning first** (the existing `_complain` behaviour, which raises only under `strict=True`), so no downstream run breaks on upgrade; flip to unconditional raise once P0.2/P0.4 have landed everywhere. Roll out via `para-drift` in the same sweep as P1.2/P1.3.

### P1.2 · Hub: add the two missing public accessors
Two private-attribute reaches in downstream code exist because the public API has gaps, not because the authors were careless.

- **`ParadataLogger.run_id`** — `atrium_paradata.py` exposes only `_run_id`. Add `@property def run_id(self): return self._run_id`. **This must land before** the long-standing "replace `_logger._run_id` with `_logger.run_id`" cleanup becomes actionable — the property does not currently exist, and `alto/document_hook.py:60` already assumes it does (see P2.1).
- **`DocumentRecord.get_block(name)`** — the only way to read a block today is `to_dict()` (a full deep copy) or `doc._data`, which is what the translator does. Add a read accessor returning a deep copy.

Also fix the template's own docstring example (line 139), which teaches `run_id=logger._run_id` — every downstream repo copied it.

### P1.3 · Hub: reconcile schema ↔ ownership table
- Add `lemma`, `upos`, `feats` to the schema's `lines[]` properties — `BLOCK_FIELD_OWNERS` grants them and the schema does not describe them (`additionalProperties: true` means validation will never notice).
- Apply whatever `entities[]` key decision comes out of P0.3.
- Apply whatever `translations` shape decision comes out of P0.5.
- Consider tightening `additionalProperties` on the *content* blocks from `true` to `false` for the fields the contract actually governs, keeping `true` at the top level (rule 6 requires unknown top-level blocks to pass through, but it does not require unknown *fields* inside a governed block to pass silently).

### P1.4 · Hub: extend `e2e-pipeline-smoke.yml` to carry a document JSON — **the single highest-value item in this plan**
`e2e-pipeline-smoke.yml` chains all five tools over one fixture across 556 lines and contains **zero** occurrences of `document`. Every P0 finding would have been caught by one run of a chain that passes the record along.

Thread `<doc_id>.document.json` through the five existing stages as an artifact and assert, after each:

1. **Own fields changed** — the stage's declared block/fields differ from the input.
2. **Nothing else changed** — every other block is byte-identical to the input (this alone catches P0.2, P0.4, and the P0.5 shape drift).
3. **Row counts are stable** — `len(entities)` and `len(lines)` never *decrease* across a stage (catches P0.3's silent collapse).
4. **The record landed where it was asked to** — assert the path, not just existence (catches P0.1).
5. **Final validation** — the end-of-chain record validates against `atrium_document.schema.json`, and `assembled.blocks` names all five programs with non-empty `run_id` **and** `paradata_ref`.
6. **Licence accretion** — `provenance.license_detail` reflects the most-restrictive union of all five stages.

Also add a **no-baseline leg**: run each tool standalone with no `--document-json` and assert the output is a valid partial record (rule 3).

### P1.5 · Add a pytest workflow to all five tool repos
No repo runs its unit tests in CI — `pre-commit` is `ruff` + `shellcheck` only. Every 🟢 in the 2026-07-26 status table meant "lint and drift pass", not "the tests pass". Add a reusable `pytest.reusable.yml` to the hub and call it from each repo, so that the local suites (which do exist and are reasonably good) become a gate.

While doing so, fix the two suites that certify code they never execute:
- `nlp-enrich/tests/test_document_hook.py:10` patches `DocumentRecord` with a `MagicMock` and asserts only that the hook was *called* — it cannot see P0.1, P0.2 or P0.3. Replace with a real `DocumentRecord` against `tmp_path` and assert on the written file.
- `alto/tests/test_document_hook.py` passes a `MagicMock` logger, which answers `logger.run_id` even though `ParadataLogger` has no such attribute — masking P2.1.

### P2.3 · `llm-enrich`: stamp `paradata_ref`
None of the four call sites (`llm_run.py:501`, `ollama_client.py:301`, `openrouter_client.py:366`, `service/api.py:250`) pass `paradata_ref`, so `assembled.blocks.enrichment.paradata_ref` is always `""`. Compute it the way alto's `paradata_ref_for()` does and pass it through `write_document_record()`.

### P2.4 · Converge `doc_id` derivation across all five tools — **cross-repo, needs one decision**
The record's primary key is derived four different ways: `name.split(".")[0]` (translator), `Path.stem` (nlp-enrich, llm-enrich ollama/openrouter), `teitok_read.doc_id_from_path()` (llm-enrich `llm_run`), the `FILE` column (page-classification). On `CTX000000001.alto.xml` these produce `CTX000000001` and `CTX000000001.alto`; on `CTX000000001.udpipe.conllu`, `CTX000000001` and `CTX000000001.udpipe`. Two tools then write two records for one document and nothing detects it.

Add a canonical `doc_id_from_path()` to the **hub template** (so it travels under `para-drift`), specify the rule once — recommended: strip all known pipeline suffixes (`.alto.xml`, `.teitok.xml`, `.conllu`, `.md`, `.categories.json`, …) then `split(".")[0]` as the floor — and route all five tools through it. Add a case to the P1.4 smoke that feeds a multi-dot filename end-to-end.

### P2.5 · Converge the CLI/API I/O shape
Two incompatible conventions are in use: file-pair (`--document-json` / `--document-json-out`) and in-place directory (`--document-json-dir`). `document_schema.md` rule 1 names only the file-pair form, so three repos are undocumented. **Adopt page-classification's solution** — it already implements both cleanly as two separate functions rather than one overloaded kwarg pair (`write_document_record` / `write_document_records_dir`), and its docstring explains exactly why. Give every tool both shapes, and update rule 1 in `document_schema.md` to describe them.

### P2.6 · Make record writes atomic
`DocumentRecord.finalize()` writes in place; a crash mid-write leaves a corrupt record that fails the next tool's `load_document()`. page-classification already does `tmp` + `replace` and documents the reasoning. Move that into `finalize()` in the hub template so all five repos inherit it, and drop the local workaround.

### P2.7 · Small warts

- `nlp-enrich/api_util/document_hook.py:109-113` — `include_lines` logs a warning then `pass`. Either implement the `lines[]` morphology merge (it is the only source for the `lemma`/`upos`/`feats` fields the ownership table grants) or remove the flag and its `api_4_stats.sh:48` plumbing.

Both are written by page-classification from the same `CLASS-1` column, so they cannot disagree today — but nothing enforces that. Recommendation: keep `pages[].category` as normative and make `page_categories` a documented convenience projection, or drop it.

## P3 — New capability

### P3.1 · `llm-enrich`: build `api_util/json_to_md.py`
**Recommendation: build it.** Rationale in `13.digest.md` §5. Sketch:

```
api_util/json_to_md.py
  load_document(path)                       # from atrium_document
  → rows   = [{page_num: int(l["page"]), line_num: l["line"],
               text: l["text"], bbox: l.get("bbox")} for l in doc["lines"]]
  → pages  = {int(p["page"]): {"width": p["canvas"]["width"],
                               "height": p["canvas"]["height"]} for p in doc["pages"]}
  → xml_to_md.rows_to_layout_markdown(rows, pages, title=doc["doc_id"])
```

plus the cues only the JSON plane can fill (`NEEDS_OCR` from `pages[].needs_ocr`, `OCR: engine=…, lang=…` from `pages[].ocr`) and the quality filter only the JSON plane has (drop `lines[].categ in {Garbage, Inverted}`, offer `--min-quality`). Implement `--detail full|standard|minimal` here — the enum already exists in the schema's `regenerable.detail` and is unimplemented everywhere.

**Two constraints, both non-negotiable:**
- Read **only** `pages`, `lines`, `content`. Never `enrichment` — llm-enrich writes that block, and reading it would feed the model its own prior output on a second run.
- Fallback ladder `lines[]` → `content.text` (unsectioned, warn) → explicit error. Never emit a structureless dump silently.

Register for `*.document.json` in `doc_to_visual_md.py`'s dispatcher so there stays one entry point. Then switch `llm_client_shared.write_document_record()`'s recipe to `{"from": f"{doc_id}.document.json", "converter": "json_to_md@1.0", "detail": detail}` — which is what makes the record self-regenerating rather than a dangling pointer at a TEITOK file the consumer may not hold.

### P3.2 · Consider the `BlockPolicy` refactor before a second schema exists
From `13.digest.md` §6: the mechanism in `atrium_document.py` is fully schema-agnostic (~480 of 589 lines); the binding to *this* schema is ~50 lines of module-level constants with **no injection point**, so adaptation means forking the file and one process can only ever serve one schema.

A `BlockPolicy` dataclass — `{owners, field_owners, key_fields, reserved, order, record_type, file_suffix, id_field, license_merger}`, defaulted to `ATRIUM_POLICY`, accepted as `DocumentRecord(..., policy=…)` — is ~40 lines, fully backward-compatible, and converts all three limits at once. Worth doing **now**, while there is one schema and one place to change, rather than after a second design forces a fork. Low priority against P0/P1, but it gets more expensive the longer it waits.

### P3.3 · Deferred, unchanged
- Reserved cue emitters (`LAYOUT_COLUMN`, `WATERMARK`, `INDENT`, `STYLE` line-spacing, `FONT` weight).
- The #22 token-cost bake-off across `full`/`standard`/`minimal` — becomes cheap once P3.1 implements the three profiles in one place.
- Unifying `nlp-enrich` onto annotated-MD input (digest §D.1, the oldest open item) — P3.1 is its prerequisite.
- De-duplicating the LLM engine (`llm_utils`/`vocab_manager`/`llm_run`) across `llm-enrich` and `nlp-enrich`, currently outside `para-drift`.
- The FAIR/PID population (`entities[].pid`: Wikidata/GeoNames/AAT/AMCR) — the field exists and is always null; the ARIADNE/GoTriple hook is unbuilt.

## Release gate

Before promoting any of this from `test` to `main`, all five must hold:

1. **P0.1-P0.6 landed** — the chain completes end to end without losing a field.
2. **P1.4 green** — the e2e smoke carries a document JSON through all five stages and asserts pass-through, row-count stability, destination, licence union, and final schema validation.
3. **P1.5 green** — pytest runs in CI in all five repos, with the two mock-only document suites replaced by real ones.
4. **The no-baseline leg passes** for every tool (rule 3).
5. **`para-drift` still green** after the hub changes in P1.1-P1.3 propagate.

Only then does the 2026-07-26 recommendation "promote the validated `test`-branch changes to `main`" become safe. As of this refresh, item 2 has never run and items 1 and 3 are unmet — so the ecosystem is **integrated but not validated**, and the two should not be conflated in the release notes.
