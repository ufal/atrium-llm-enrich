## P5 — The TEITOK input path (with atrium-nlp-enrich's round 4) — ✅ implemented 2026-09-24

As built: `llm_client_shared.row_quality()` / `llm_utils._row_quality()` return None for a missing score and the
filters skip the quality bands for it (the output record carries `"quality_score": null`); the GPU path passes it;
`tests/conftest.py`'s `stub_llm` replaces only `make_chat_fn`. `teitok_read.py`, `flexiconv_convert.py` and
`tests/test_flexiconv_convert.py` are re-vendored and re-pinned; nlp-enrich's released `CTX000000002` (a `<pb/>`
inside s-5) is pinned as `tests/fixtures/teitok/writer/CTX000000002.teitok.xml` (the parity test's new `SOURCE`
map names its path there). `xml_to_md._read_teitok_layout` now uses the reader's page model: one line per page
part of a sentence, each with its own page's box, lines numbered per page, `## Page I` for a labelled page, and
`DOC_META … origin=printspace`. Evidence: `pytest -m "not slow"` 947 passed, 18 skipped; torch-gated
`tests/test_llm_utils.py` passes with a stub. CONTRIBUTING no longer claims `llm_utils.py` is a verbatim copy.
The steps as planned:
### P5.1 · Rows without a quality score are processed, not trashed
`read_input_rows()` (`llm_client_shared.py:163-178`, `llm_utils.py:1846-1858`) gives TEITOK rows `quality_score: 0.0`;
`should_process_line()` maps < 0.40 to "Trash" (`llm_client_shared.py:126-135`, `llm_utils.py:1812-1822`), so a
`.teitok.xml` enriches nothing — and a CSV without the column is hit the same way (`float(… or 0.0)`). Make a missing
score `None` = "unknown": skip the quality bands, keep the length rules (the 06-15 design intent). Drop the
`should_process_line` patch from `tests/conftest.py` (`stub_llm`) and assert that TEITOK rows reach the model.

### P5.2 · GPU path argument count
`llm_utils.py:2059` and `:2301` call `_should_process_line(text, categ, include_non_text, …)` without
`quality_score`; every row raises and the batch loop swallows it. Pass the score (P5.1 semantics). atrium-nlp-enrich's
`llm_utils.py` copy has the same two bugs (`:1691`, `:1933`) and is fixed in its round 4.

### P5.3 · Re-vendor and a format-2 fixture
When nlp-enrich lands its round 4: copy `api_util/teitok_read.py` (line numbers per page; a sentence that contains a
`<pb/>` gives one row per page part) and `api_util/flexiconv_convert.py` (exit code when flexiconv is missing), run
`python3 tests/test_vendored_teitok_parity.py` and paste the new pins; vendor nlp-enrich's
`tests/fixtures/teitok/CTX_valid.teitok.xml` (format 2) and test `teitok_read`/`xml_to_md` on it.

### P5.4 · `xml_to_md` and the bbox origin
Read the writer's `<application ident="atrium-nlp-enrich">` `<desc>bbox origin: …</desc>`; when it says `printspace`,
say so in `DOC_META` so the model is not told PrintSpace-relative boxes are page boxes.

## P6 — Decisions left open on purpose
### P6.1 · JSON → TEITOK back-projection
The 07-24 draft drew an arrow "JSON → TEITOK `<name>`/notes" and said it already existed. It never did. If TEITOK is
to carry LLM keywords, TEATER categories or page categories (ufal/flexiconv#1 asks for keywords per page and page
categories), someone must choose the TEITOK encoding (there is no upstream convention: `<note>`, `<interpGrp>`, `pb`
attributes …) and the owner (nlp-enrich writes TEITOK; llm-enrich owns the enrichment). Until then TEITOK carries
linguistic annotation and layout only.
### P6.2 · `--detail standard|minimal` and the reserved cues
Unchanged: gated on the #22 token-cost bake-off.
### P6.3 · `entities[].translation_en`
Unchanged: reassign ownership (nlp-enrich or llm-enrich run after `entities[]` exists) or add a second translator
pass — a product decision.
