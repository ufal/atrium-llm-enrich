## P1 — Close the hole that let the incident happen (highest priority, unchanged from before, now with live evidence)

### P1.1 · Add a pytest CI workflow to all five tool repos
**This is no longer a "nice to have for coverage" — a real class-level API break shipped past 357 passing local tests and 0 CI-visible test failures.** `pre-commit` in every repo is lint/format only (`ruff`, `shellcheck`); nothing runs `pytest` in CI. Add a reusable `pytest.reusable.yml` to the hub (mirroring the existing `pre-commit.reusable.yml`/`para-drift.reusable.yml` pattern) and call it from each of the five tool repos.

While doing so, specifically target the blind spot the incident exposed: **grep every test suite for places that instantiate a real `ParadataLogger`/`DocumentRecord` but then read a private attribute (`_run_id`, `_license_block`) instead of the public accessor**, or that substitute a hand-written fake (`FakeParadataLogger`, `MagicMock`) whose interface was hand-maintained rather than derived from the real class. Both patterns will pass today and both would have hidden the incident just fixed. At minimum, one CI-running test per repo should instantiate the *real* `ParadataLogger` and read `.run_id` / `.get_license_block()` off it — the digest confirms no such test currently exists in `atrium-translator`.

### P1.2 · Thread a document JSON through `e2e-pipeline-smoke.yml`
Still the single highest-value structural item, and now doubly evidenced: this hub-level, 556-line workflow chains all five tools over one fixture and would have caught every defect fixed in this pass (the nlp-enrich crash, alto's API `set_blocks` bug, translator's `translations` shape) automatically, in one place, without needing a human to notice. It currently contains zero references to `document`.

Minimum viable version: thread `<doc_id>.document.json` as an artifact through the five existing stages and assert, after each — (1) the stage's own block/fields changed, (2) every other block passed through byte-identical, (3) `entities`/`lines` row counts never *decrease*, (4) the record lands at the path the stage was told to write it to, (5) the final record validates against `atrium_document.schema.json` with `assembled.blocks` naming all five programs and non-empty `run_id`+`paradata_ref`. Add a no-baseline leg per tool (rule 3).

## P2 — Convergence items carried over, unchanged priority

### P2.1 · Wire `canonical_doc_id()` into the five tools' own doc_id derivation
The hub function exists and is unit-verified (`CTX000000001.alto.xml` / `.udpipe.conllu` / `.teitok.xml` / `.document.json` all correctly resolve), but none of the five call sites (`translator/main.py:245`, `llm-enrich`'s three entry points, `nlp-enrich/summarize_nt_udp.py`) use it yet. The four-way doc_id divergence the digest originally flagged (`Path.stem` vs `name.split(".")[0]` vs a bespoke stripper vs a CSV column) is therefore **unchanged in practice** — the fix is built but not switched on. This is a live-behavior change to what key five independently-scheduled pipelines file documents under, so land it as its own small, reviewed PR per repo rather than bundled with anything else.

### P2.2 · Converge the CLI/API I/O shape onto page-classification's dual support
Still open: `alto`/`llm-enrich`/`nlp-enrich` support only the `--document-json-dir` directory form; `translator`/`page-classification` (single-doc path) support the file-pair form. Page-classification already implements both cleanly as two separate functions — port that pattern to the other three.

### P2.3 · Entity translation (`entities[].translation_en`)
The dead code was removed from translator (not reordering the pipeline or adding functionality speculatively — see the prior plan's P0.6 reasoning, unchanged). If the team wants this field populated, it requires a product decision: reassign ownership to nlp-enrich or llm-enrich (both run after `entities[]` exists), or add a second translator pass after nlp-enrich. `BLOCK_FIELD_OWNERS["entities"]["translator"]` is left dormant in the hub template pending that decision.

### P2.4 · Normalise alto-postprocess's stage-level paradata `program` names
Still deferred (`langID-classify` vs `langID-aggregate` vs `alto-postprocess`), as in every prior pass. The document-plane `PROGRAM_NAME` constant already shields the `atrium_document` blocks from this inconsistency, so it's a paradata-only cleanup with no document-schema urgency.

## P3 — New capability, lower priority

### P3.1 · The `--detail standard|minimal` down-profiles
`json_to_md.py` raises `NotImplementedError` for anything but `detail="full"` today, deliberately rather than silently downgrading. Implementing the two down-profiles (drop typography-only cues / structure-only) is now cheaper than before since there's one converter (`json_to_md.py` + `xml_to_md.py`'s shared renderer) rather than three to retrofit — but still gated behind the #22 token-cost bake-off this was always deferred to.

### P3.2 · `BlockPolicy` refactor for schema reuse
Unchanged from the prior plan: worth doing before a second JSON schema design exists in the ecosystem, not urgently — nothing needs it today.
