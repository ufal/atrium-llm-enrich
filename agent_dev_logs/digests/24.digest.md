## ✅ What's already known (from this repo's own prior research, not from this thread)
- **olmOCR is not new information here.** It's already listed in `plans/10.plan.md` §2c as one
  of the OOTB VLM transcribers earmarked for the **hub #22** document-understanding benchmark,
  cross-referenced there rather than decided on directly — the same treatment CHURRO-3B,
  Qwen2.5-VL, SmolDocling-256M, dots.ocr and DeepSeek-OCR got.
- **The benchmark harness this candidate would run through already exists in this repo**:
  `eval_metrics.py` (CER/WER, normalized edit distance, entity F1, optional TEDS) and
  `sample_stratify.py` (quality-stratified 80/10/10 page sampling), landed 2026-07-12 for hub
  #22's "Concrete First Step" comparison. Nothing has run through it yet for any VLM candidate,
  olmOCR included — hub #22 itself is still at the research/methodology stage per that issue's
  own digest.
- **This repo's own OCR path (#10) already has a working, opt-in engine** — Tesseract `ces`,
  landed for the render+OCR (scanned/curve-only PDF) branch — with **PERO-OCR** benchmark-gated
  as the next comparison at that same seam. olmOCR would be a *third* candidate at that seam, not
  a replacement for a decision already made; nothing in #10's plan currently names it as favored
  over PERO-OCR.
