## 2. The contract (moved from the hub copy; still valid unless marked)
**Three planes, one job each**, bound by paradata `run_id`:

| Plane                 | Format                                             | Role                                              | Authority                        | Produced by                                                             |
|-----------------------|----------------------------------------------------|---------------------------------------------------|----------------------------------|-------------------------------------------------------------------------|
| Reading               | annotated Markdown (`## Page N` + `<!-- cues -->`) | LLM input                                         | derived, disposable, regenerable | `pdf_to_md` / `docx_to_md` / `xml_to_md --format layout` / `json_to_md` |
| Layout / preservation | TEITOK XML (format 2 since nlp-enrich v0.21.0)     | human view, CQP/XPath search, correction, archive | spatial source of truth          | atrium-nlp-enrich `teitok_alto.write_teitok_merged`                     |
| Search / knowledge    | `atrium_document` JSON record                      | text, metadata, entities, enrichment for indexing | canonical semantic record        | every tool accretes its block (`atrium_document.py`)                    |
| *(invariant)*         | paradata JSON (`atrium_paradata`)                  | provenance, licence, run binding                  | immutable audit trail            | every stage                                                             |

- **HTML-fragment detail:** full `CUE_SCHEMA` by default (`api_util/layout_md.py`), aggregated at block level
  (word/line coordinates stay in TEITOK); cues are positional hints, never content; `standard`/`minimal` down-profiles
  via a `--detail` knob — still `NotImplementedError` in `json_to_md.py:235-240` (deferred to the #22 bake-off).
- **JSON template → built:** `atrium_document.schema.json` + `atrium_document.py` are hub-canonical
  (`atrium-project/docs/templates/shared/`), vendored byte-identically, documented in hub `docs/document_schema.md`.
  Review round 1 is honoured: the record references only originals and persistent step outputs (`derived_from`),
  disposable derivations are recipes (`regenerable`, e.g. Markdown via `json_to_md`), no page-image paths.
- **Aggregate:** the 07-24 "aggregator service" idea was superseded by **accretion** — each tool reads the record,
  merges its own block (`merge_block`), and passes it on; `assembled.blocks` names the contributors.
- ❌ **Correction (2026-09-24):** the 07-24 draft said the JSON→TEITOK re-projection "already exists
  (`teitok_alto.py`)". It does not: `teitok_alto.py` writes TEITOK from CoNLL-U + ALTO; nothing writes LLM keywords,
  TEATER categories or page categories back into TEITOK, in any repo. That arrow is a design option, not a fact — it is
  also what ufal/flexiconv#1 asks for (keywords per page, page categories) and is listed under §5.
