## 🎯 Goal
Turn the issue's three candidate formats — **MD+HTML** (LLM input), **TEITOK.XML** (visually-correct
layout), **JSON** (search / metadata / additional info) — into one coherent, FAIR architecture, and
specify the two open items: **how detailed the HTML fragments are** and **the JSON schema template**.
Neither a data-formats design doc nor a standalone JSON schema existed in the ecosystem before this.

## 🧭 The answer in one picture
**Three planes, one job each**, bound by paradata `run_id`:
- **Reading — annotated Markdown** (`# doc` + `## Page N` + `<!-- cues -->`): the LLM diet, **derived
  & disposable**, regenerated from the layout plane. `pdf_to_md`/`docx_to_md` · `xml_to_md --format layout`.
- **Layout — TEITOK.XML** (TEI + facsimile + bbox): the **spatial source of truth**; human view,
  CQP/XPath search, correction, archival. `nlp-enrich/api_util/teitok_alto.py`.
- **Search — JSON document record**: the **canonical semantic record** for indexing / ARIADNE-GoTriple
  export, harmonising the existing enrichment + paradata + entity schemas.
- Markdown regenerates from TEITOK; TEITOK persists; the JSON accretes across tools. Nothing
  circular, and **no transient artifact is ever referenced**.

## 🔎 Spec 1 — HTML-fragment detail: **full `CUE_SCHEMA` by default**
Markdown is a throwaway view, so emit **every** recoverable cue as inert HTML comments
(`layout_md.CUE_SCHEMA`: 15 comment cues + 8 inline GFM forms). Kept faithful, not bloated, by two
invariants: **aggregate at block level** (word/line coords stay in TEITOK) and **cues are positional
hints, never content**. `standard`/`minimal` down-profiles stay selectable via a future `--detail`
knob; the token-cost check rides with #22. Several cues remain **defined-but-reserved** (`weight`,
`INDENT`, `LAYOUT_COLUMN`, `LAYOUT_MARGIN`, `STYLE` line-spacing, `WATERMARK`).

## 🔎 Spec 2 — the JSON record, built as a **paradata pair**
One canonical, versioned, FAIR record per document — and, per motyc's redirect, **not** produced by a
central service. It travels *with* the document: each tool takes the previous version, if given one,
and returns it with **only its own block** updated.

```
doc.json ──► [alto] ──► doc.json ──► [nlp] ──► doc.json ──► [llm] ──► doc.json
              pages/lines           entities            enrichment
```

**Six rules:** ① optional `--document-json` in / out · ② **own block only**, everything else passes
through untouched · ③ **no baseline → own part only** (standalone-safe) · ④ each block stamped with
its writer's `program`/`run_id`/`paradata_ref` (granularity) · ⑤ licenses accrete via
`para_licenses.merge_effective_licenses` · ⑥ unknown/newer blocks preserved, newer major refused.

**Ownership** is one-per-block, with field-level splits where several tools contribute (`pages`,
`lines`, `entities`), so nothing is co-mutated.

**Reference discipline:** only the **original input** (keyed `doc_id` + `sha256`) and **persistent
step outputs** (`derived_from`). Markdown and page images are *disposable*, so they appear in
`regenerable` as a recipe — never as a stored path.

**Why it fits:** `atrium_paradata.py` already has the round-trip primitive
(`_to_state_dict`/`_from_state_dict`, the `load_paradata` version guard, `merge_run_paradata`), and
~17 `ParadataLogger` sites across the five tools are exactly the seams the paired hook attaches to.

  blocks survive **byte-identical** and the record validates against the schema.
